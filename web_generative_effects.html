Web Generative Effects / 01

状態変化を、
そのサイトの世界観にする。

水・炎・雷・草花——「何かが変化していく様子」をコードで生成し、業種に合わせて転用する。ロゴではなく、サイト全体の背景・ヒーローセクション・トランジションへの応用が目的。

02 / Concept

「状態変化」は、
業種のメタファーになる

気象・物理現象は、そのまま業種のブランドイメージと結びつきやすい。技術は使い回せても、色とモチーフを変えるだけで別の業種に転用できる。

状態変化技術合うサイト例
水面・波・光の屈折WebGL / GLSLプール、海、リゾート、水族館
炎・熱・粒子の上昇Canvas + JSキャンプ、焚き火、暖炉、アウトドアブランド
雷・放電・回路の光Canvas + JSロケット、宇宙、先端技術、ガジェット企業
成長・分岐・開花Canvas + JS植物園、公園、農園、サステナ系ブランド
雪・結晶・氷結Canvas + JSスキー場、冬季イベント、ラグジュアリー系

この後、上から4つ + ボーナス1つを実際に動くデモで見せる。

03 / Water

水：光の屈折を
三角関数で合成する

初期化中… 
for (int i=1;i<=3;i++){
  float fi=float(i);
  c += sin(p.x*fi*4.0+t*.6+p.y*2.0)
       *(0.5/fi);
  c += sin(p.y*fi*3.0-t*.4+p.x*1.5)
       *(0.5/fi);
}
// wave 0-1 を深海色→浅瀬色→泡色へ mix

プール・海・水族館サイトのヒーロー背景。ノイズ関数を使わず sin の重ね合わせだけなので、GLSLコンパイルが壊れにくい。

転用のコツ：deep/shallow/foamの3色を変えるだけで「温泉」「氷結した海」にも流用できる。

04 / Fire

炎：上昇する
粒子で熱を表現する

p.vy *= 0.985;      // 上昇が徐々に減速
p.life -= 0.016;    // 寿命で透明化
g = radialGradient(p.x,p.y,size);
g.addColorStop(0, orange*life);
g.addColorStop(1, transparent);
ctx.globalCompositeOperation
  = 'lighter';       // 重なるほど明るく

キャンプ・焚き火・暖炉・アウトドアギアのサイト。ボタンhoverや「読み込み中」演出にも小さく転用可能。

転用のコツ：色を橙→紫にして上昇速度を上げると「魔法のエフェクト」、下降させて灰色にすると「煙・霧」になる。

05 / Lightning

雷：中点変位法で
放電の形を生成する

function branch(x1,y1,x2,y2,disp,depth){
  if(depth<=0) return [[x1,y1,x2,y2]];
  const mx=(x1+x2)/2+(rand-.5)*disp;
  const my=(y1+y2)/2+(rand-.5)*disp;
  return [...branch(x1,y1,mx,my,disp/1.9,depth-1),
          ...branch(mx,my,x2,y2,disp/1.9,depth-1)];
}
// shadowBlur でグロー、乱数で分岐も追加

ロケット・宇宙・先端技術・ガジェット企業のサイト。回路基板の光の走りや起動アニメーションにも応用しやすい。

転用のコツ：青白い光を緑にすると「マトリックス的なテック感」、横方向にすると「基盤の電流」になる。

06 / Flora

草花：再帰分岐で
成長そのものを描く

function walk(x,y,len,angle,depth,n){
  const localT = clamp(
    (t - depth/maxDepth) * maxDepth, 0, 1);
  // localTが枝ごとの「伸びる進捗」
  draw(x,y,x2,y2);
  if(localT>=1){
    walk(x2,y2,len*n.lenFactor,angle-n.spread,...);
    walk(x2,y2,len*n.lenFactor,angle+n.spread,...);
  }
}

植物園・公園・農園・サステナブル系ブランドのサイト。スクロールに合わせて成長を進める演出に向く。

転用のコツ：枝を白・氷色にすると「霜の結晶」、赤に近い色で先端に丸をつけると「血管・神経」のような医療系ビジュアルにもなる。

07 / Bonus — Snow

ボーナス：雪も
同じ発想で数分で作れる

f.y += f.vy;                 // 落下
f.x += Math.sin(t+f.drift)*.3; // 横揺れ
if(f.y>h){ f.y=-4; f.x=rand*w; } // 上に戻す

スキー場・冬季イベント・ラグジュアリー系サイト。粒子の速度・揺れ幅を変えるだけで「桜吹雪」「花粉」「灰」にも流用できる。

水・炎・雷・草花の4系統と組み合わせ元は同じ：粒子 or 数式で「状態」を表し、時間で変化させる。

09 / How to choose

業種から逆算して選ぶ

業種おすすめ演出技術実装難度負荷の目安
プール・海・水族館水WebGL★★★中（GPU依存）
キャンプ・アウトドア炎Canvas★★低〜中（粒子数で調整）
宇宙・先端技術・ガジェット雷Canvas★★低（間欠的に発生）
植物園・公園・サステナ草花Canvas★★★低（一度生成すれば軽い）
スキー・冬季・ラグジュアリー雪Canvas★低

現実的な優先順位：まずCanvas系（炎・雷・草花・雪）を先に固める。WebGLは水だけに絞って確実に動かす方が、全体の完成スピードが上がる。

10 / Implementation

1つのコンポーネントに
抽象化する

type: water/fire/lightning/flora/snow→color→intensity→speed 
<GenerativeBackdrop
  type="fire"
  palette={["#ff8a3d","#ffcf6b"]}
  intensity={35}
  speed={1}
/>

// 内部では type ごとに
// initWaterEffect / initFireEffect / ...
// を呼び分けるだけ。DOM構造とcanvasは共通

今のReactの仕事とそのまま接続できる。typeを切り替えるpropsにしておけば、業種違いのサイトが増えても同じコンポーネントを使い回せる。
